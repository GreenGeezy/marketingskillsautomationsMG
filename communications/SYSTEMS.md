## Delivery path

**Where to confirm product claims.** Use the live listing for the intended platform and region. The store identifiers used by the website are [MasterGrowbot AI on iOS](https://apps.apple.com/us/app/mastergrowbot-ai-grow-cannabis/id6752221060) and [MasterGrowbot AI on Android](https://play.google.com/store/apps/details?id=com.mastergrowbot.app). The iOS audit checkout's Git origin points to the Vone repository's ios branch. For mobile features, compare the release actually available in that store with the matching tag or branch.

```text
LinkedIn byline → tagged website tool or newsletter → explicit signup request
Website POST /api/newsletter/subscribe → Formspree + optional Apps Script/Sheet
                                     → Resend transactional confirmation
Reader opens confirmation → explicit POST → authenticated proof in owner's Gmail
Private reconciliation → eligible Resend segment(s), honoring cadence and losses
Resend owner preview → delivered + 48h review window → eligible customer broadcast
Verified customer delivery → archive final sent version in website repo → Vercel
Replies → newsletter@mastergrowbot.com → ImprovMX → owner's Gmail
```

**Domain routing.** Public DNS at inspection returned ns1.dns-parking.com and ns2.dns-parking.com for the apex, ImprovMX servers for apex MX, and cname.vercel-dns.com for www. Hostinger is the domain/DNS management context. The website's `index.html` Content Security Policy permits Cloudflare domains including challenges.cloudflare.com for embedded flows. That permission establishes neither Cloudflare authoritative DNS nor a Cloudflare Worker for newsletter sending. No Worker was identified in these two delivery paths. On migration, resolve NS, MX and www CNAME again and inspect deployment aliases and any separately configured Cloudflare route **for the exact hostname**. Preserve challenge support for checkout. A marketing handoff requires no DNS, Cloudflare, CSP or proxy changes. Keep support forwarding and root MX intact.

**Outbound.** Resend sends confirmations and broadcasts. Public sender is Cannabis AI News & Tools <editor@news.mastergrowbot.com>; Reply-To is newsletter@mastergrowbot.com. ImprovMX forwards incoming replies. Gmail receives consent receipts, owner previews and opt-outs. Gmail SMTP is outside the bulk delivery path. The private launch record documents an owner rehearsal with passing SPF, DKIM and DMARC and a one-click unsubscribe returning 204 with the provider contact marked unsubscribed. To revalidate after material mail changes, inspect a new isolated owner-only message's original authentication headers, reply path and provider suppression. A historic pass cannot establish current inbox placement.

**Signup handler.** In the website repo read `api/newsletter/subscribe.js`, `api/newsletter/confirm.js`, `api-lib/confirmation.js`, `api-lib/newsletter.js`. POST uses normalized email, sourcePage, sourceForm, interestProduct and four UTM fields (source, medium, campaign, content). The current allowlist is `newsletter`, `newsletter_page`, `homepage_newsletter`, `newsletter_workbench_climate`, `newsletter_workbench_stock`, `newsletter_workbench_sop`, `newsletter_home_journal`. A new physical form must align the allowed value, UI, attribution and tests. Preserve original UTMs on internal hops. A central form following a referral is a different placement from an embedded form. Read the response flags separately: setupRequired, formspreeSaved, googleLeadSaved and confirmationSent. HTTP 200 can be setup-only or capture without confirmation.

**Formspree and Google Drive.** Formspree is the established intake record. Form configuration can use the source default. The optional Google path is a Drive-hosted Sheet and an Apps Script web-app deployment, not website hosting or the subscriber database. The referenced spreadsheet's MIME type was independently confirmed through Drive metadata. In the Vercel environment-key listing for the live www alias, RESEND_API_KEY was visible and the two optional Google webhook keys were absent from the returned listing. This audit did not establish active Google mirroring. Run both jobs using verified Formspree records even when the optional mirror is off.

The Apps Script reference lives at `docs/google-apps-script-leads-webhook.js` in the website repo. Its configuration contains private bindings. Inspect privately. Its doPost checks the configured shared secret, validates email, opens the bound sheet/tab, appends timestamp, email/name, source page/form, product, UTMs, user agent and payload with the secret removed, then sends an owner notification. A notification failure can follow a successful append. A ContentService error body may arrive with HTTP 200. If relying on this path, verify production project/target, deployment version, owner access, destination tab and matching secret without displaying values. Use one isolated, consenting owner test; require JSON ok:true, the row with matching attribution, and notification. Match records across stores; count a form submission once. Existing Drive access alone proves neither deployment nor delivery.

**Secrets and roles.** Server configuration names include RESEND_API_KEY, optional NEWSLETTER_CONFIRM_SECRET (fallback is the send key), FORMSPREE_NEWSLETTER_FORM_ID, GOOGLE_LEADS_WEBHOOK_URL and GOOGLE_LEADS_WEBHOOK_SECRET. Keep them server-side. Key rotation can invalidate outstanding confirmation links. The website mail credential was send-only at handoff. Segment reconciliation and broadcasts require the authenticated Resend dashboard or a separately authorized equivalent. A legacy RESEND_NEWSLETTER_SEGMENT_ID helper does not grant that permission. The retired `api/newsletter/monthly-send.js` returns 410. Never recreate it as a second sender.

**Consent.** The confirmation is a signed, day-based HMAC link valid while age in days is 0–6. Token in the URL fragment; GET displays a form and removes the fragment from the address bar; explicit POST sends the authenticated receipt titled “Confirmed opt-in | Cannabis AI News & Tools”. The website uses per-request/per-proof provider idempotency. Keep the inbox, tokens and receipt IDs private. Verification reads email and issue-day from the payload while new tokens carry “weekly” as a third field. Older tokens can therefore yield a receipt with weekly wording. Check the original form/promise and dated evidence before classifying legacy readers. Unclear consent or cadence stays out pending reconciliation.

**Sales and measurement.** GA4 and the site's `src/lib/analytics.ts` measure tagged traffic and interactions. RevenueCat/App Store Connect/Google Play record app subscription events. Use merchant reports for proceeds and refund/date/region differences. GrowTech and eligible digital playbooks use Whop Elements with hosted fallback; `docs/whop-elements-migration-2026-10-08.md` describes payment vs setup callbacks. Verify actual paid Whop records. Amazon KDP reports orders/royalties separately; an Amazon link click alone has no purchase attribution. None of these systems grants newsletter consent.
